培小评 · 演示视频脚本

建议时长：4分30秒 | 录制工具：OBS / Windows 系统录屏 / 剪映录屏

开场：痛点引入（0:00 - 0:40）

画面 旁白
黑底白字，逐行弹出 「一场 200 人的培训结束后，HR 需要多久看完所有人的心得？」
切换到表格截图（假装很多行） 「200 份 Word 文档，3 位 HR，每人 3 小时——而且标准不统一、面子文化导致评价失真。」
切入产品名称 「培小评——AI Agent 驱动的培训心得智能评价系统，让这个流程从半天缩短到 30 秒。」

第一节：上传文档（0:40 - 1:10）

画面 旁白
打开应用首页，展示界面 「打开培小评，首先进入上传页面。」
拖拽或点击上传 3-5 个 Word 文件 「支持批量上传培训心得 Word 文档。这里我准备了 5 份真实心得——来自不同部门、不同风格的员工。」
文件列表出现，展示文件名 「系统自动解析文档内容，无需任何格式转换。」
点击「开始评价」按钮 「点击开始评价，剩下的事交给 AI。」

第二节：AI 批量评价（1:10 - 2:00）

画面 旁白
页面切换到评价进度条 「系统逐篇调用 AI Agent 进行评价。注意这里是 SSE 流式输出——不是一次性返回，而是一篇一篇实时推进。」
播放过程中展示进度（5 篇约需 30 秒，本地运行时展示真实速度） 「每篇评价完成后，会立即显示在对话面板中。HR 不需要等待全部完成就能看到结果。」
第一篇评价卡片出现（分数、一句话点评、详细分析） 「看，第一篇已经出结果了。AI 从内容深度、逻辑表达、结合实际、情绪流露四个维度打分，并给出结构化分析。」

第三节：评价结果展示（2:00 - 2:40）

画面 旁白
展示多篇评价卡片，逐个点击展开 「每篇心得都有：总分、一句话点评、四个维度的详细分析，以及情绪语调标注。」
特写一篇高分评价 「这一篇来自销售部李明，AI 识别出其内容结合了真实客户案例，打出了 8.5 分的高分。」
特写一篇低分评价，展示红色异常标记 「而这一篇，AI 检测到内容空洞、模板化严重，只给了 3 分，并自动标记为"异常"——这对 HR 来说是重要的风险信号。」

第四节：对话追问（2:40 - 3:20）

画面 旁白
点击某个评价卡片下的「追问」或输入框 「更妙的是，培小评支持对话式交互。HR 可以追问 AI 任何关于评价的细节。」
输入「这篇心得的亮点是什么？」 「比如问：这篇心得的亮点是什么？AI 会基于原文精准回答。」
AI 回复，引用原文关键句 「或者问：为什么分数偏低？AI 会引用心得的薄弱段落，给出具体理由。」
再输入「帮我写一段给这个员工的反馈」 「甚至可以直接让 AI 帮写一段给员工的反馈话语——这就省去了 HR 绞尽脑汁组织语言的麻烦。」

第五节：异常提醒与 HR 处理（3:20 - 3:50）

画面 旁白
切换到「异常列表」页面 「所有低分评价自动进入异常列表。系统支持邮件通知——当出现评分低于 5 分的心得时，HR 会即时收到提醒。」
展示异常列表中的条目 「HR 可以在这里逐条复核、添加处理意见。比如这份 3 分的评价，HR 决定约员工面谈。」
点击「标记已处理」 「处理完毕后一键标记，形成闭环。」

第六节：价值总结（3:50 - 4:30）

画面 旁白
黑底白字，三行核心数据 「总结一下培小评带来的变化：」
「10 分钟 → 30 秒」 「单篇评价时间：从 10 分钟降到 30 秒——效率提升 20 倍。」
「100% → 低于 20%」 「人工介入比例：从 100% 降到不足 20%——只处理异常。」
「主观偏差 → 统一标准」 「评价一致性：从「每个 HR 一套标准」变成「一套标准服务所有人」。」
显示产品 Logo + 项目名 「培小评——让每一份培训心得都被认真对待。谢谢。」

录制注意事项

  1. 环境整洁：关闭不相关的浏览器标签、聊天窗口、桌面图标
  2. 字体放大：浏览器按 Ctrl + 把页面放大到 125%-150%，保证评委看清内容
  3. 鼠标操作清晰：移动慢一点、点击后停顿 1 秒再下一步
  4. 声音清晰：用外接麦克风，或者手机录旁白后期合成
  5. 不用录代码/IDE：只录浏览器页面，代码编辑器会分散注意力
  6. 提前跑通一遍：录制前先在本地启动前后端，确保 API 调用正常
  7. 后期可加速：评价进度那段如果太慢，剪辑时可 2x 加速，不影响观看

本地启动命令（录制前执行）

# 终端1：启动后端
cd D:/hr/agent/backend
npm run dev

# 终端2：启动前端
cd D:/hr/agent/frontend
npm run dev

然后打开 http://localhost:5173 开始录制。
